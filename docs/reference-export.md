# CPU reference export experiment

This fork-only instrument supports WaveScope issue
[getpwnam/wavescope#1260](https://github.com/getpwnam/wavescope/issues/1260).
It does not change WaveScope's worker image or its pinned decoder revision.
The versioned files below are an experiment format, not a WaveScope contract.

## Capture and replay

Build and install this fork using the normal installation instructions. Run
with the installed GNU Radio Python interpreter:

```sh
python3 -m gnuradio.dvbs2rx.reference capture \
  --input /corpus/m19-normal-p0-n6-nominal.sigmf-data \
  --output /results/reference.bch \
  --constellation 16APSK --code-rate 3/4 \
  --decoder-revision "$(git rev-parse HEAD)" \
  --export-dir /results/reference
python3 -m gnuradio.dvbs2rx.reference replay /results/reference
```

The input is raw little-endian complex float32 IQ, including SigMF
`cf32_le` data files generated by WaveScope's `tools/dvb_cpu_baseline.py`.
Pass `--frame-size short` and/or `--pilots` when appropriate. Defaults are
normal frames, pilots off, 2 samples/symbol, 25 LDPC trials, rolloff 0.35 and
Gold code 0. `--sps` and `--max-trials` are adjustable. This experiment's
standalone graph uses AGC, the carrier rotator, symbol timing, PL sync,
demapping, LDPC and BCH. It expects a centered signal at the supplied samples
per symbol; it is not WaveScope's channel-selection/resampling front end.
Only fixed DVB-S2 MODCODs supported by `params.translate` are accepted;
ACM/VCM and extended DVB-S2X PLS are not supported by this standalone CLI.

Without `--export-dir`, no reference taps or files are created. The only
output is `--output`: packed BCH message bytes **before** BB descrambling,
including invalid frames. This output file is overwritten. Input and output
must be different files. Export requires a new directory and an explicit
decoder revision; existing export directories are never reused.

`ReferenceExport(top, directory, config, symbols, demapper, ldpc, bch,
provenance)` can also attach to an existing fixed-MODCOD Python flowgraph.
Use the exact `plsync_cc` output feeding the demapper as `symbols`. Call
`finish()` only after `run()` or `stop(); wait()`, and `close()` in a `finally`
block. `config` contains `constellation`, `code_rate`, `frame_size`, `pilots`
and positive `max_trials`. Provenance should identify the exact input and
fork revision. Never attach to an ACM/VCM graph using a fixed decoder.

## Format `gr-dvbs2rx.reference/1`

`manifest.json` is written last, only after stage sizes, frame statuses and
SIMD-batch continuity have been checked. Missing manifests mean incomplete
exports; empty captures fail explicitly. Every binary file has a byte length
and SHA-256 in the manifest. Export preserves all attempted frames, including
LDPC/BCH failures, without success-only filtering.

| File | Layout for each receiver frame |
| --- | --- |
| `symbols.cf32` | Little-endian interleaved float32 I/Q, exact post-PL-sync XFECFRAME payload symbols entering the demapper |
| `ldpc-input.i8` | Signed int8 LLRs, deinterleaved into LDPC codeword bit order; positive means bit 0, negative means bit 1 |
| `ldpc-codewords.u8` | Hard decisions for the full post-LDPC codeword, including parity, packed MSB first |
| `ldpc-message.u8` | Actual packed LDPC stream output, the BCH codeword, MSB first |
| `bch-message.u8` | Actual packed BCH output before BB descrambling, MSB first, even on failure |

PL headers and pilots have already been consumed by PL synchronization and
are **not** included in `symbols.cf32`. These are the exact synchronized
symbols used for demapping, not a reconstruction of the on-air PLFRAME.
The manifest's `lengths` give elements per frame (complex samples for symbols,
bytes for every other file). A frame's byte offset in a file is its zero-based
`frame` ordinal times that length, times 8 for the complex-symbol file.

The global `config` identifies MODCOD numerically and by constellation/code
rate, FECFRAME size, pilots and maximum LDPC trials. Each `frames` entry has
the receiver ordinal, BCH validity, BCH correction count (`-1` means
uncorrectable), and the original `PLFRAME_SOURCE_RANGE` start/end coordinates
when present. These coordinates are input sample positions of the symbol
synchronizer, not necessarily positions in the recording if an upstream
resampler or source offset was used. A missing source range is `null`,
never an invented transmitted-frame identity. Acquisition losses emit no
decoder frame; source ranges and the input corpus annotations reveal gaps.

Each `batches` entry records `first_frame`, the number of actual SIMD lanes
(`frames`), decoder `implementation`, `batch_trials` and `batch_converged`.
Convergence and trial counts belong to the **entire SIMD batch**, not each
individual frame; do not interpret a failed batch as proof every lane failed.
The BCH status is per frame. The export enables `ldpc_reference` stream tags
using `ldpc.set_reference_export(True)` before starting the graph. These tags
retain the existing decoded-LLR PDU and batch metadata alongside actual output,
so export does not depend on draining an asynchronous message queue at EOF.

Replay checks file integrity and frame geometry before decoding. It feeds
the original int8 LLRs directly to the CPU decoder, one original SIMD batch
at a time, preserving tail-lane padding and the iteration limit. It compares
full LDPC codewords, LDPC messages, BCH bytes, batch implementation/trials/
convergence, and per-frame BCH validity/corrections. Any mismatch fails with
a nonzero exit. Successful JSON reports `ldpc_byte_identical` and
`bch_byte_identical` as true. Replay requires the same SIMD implementation;
cross-architecture quality comparisons are a separate experiment.

## Validation and timing boundaries

`ctest -R qa_reference --output-on-failure` covers QPSK, 16APSK and 32APSK,
normal/short frames, multiple SIMD batches and partial tails, byte-identical
enabled/disabled FEC outputs, failed frames, integrity rejection, invalid
batch boundaries, exclusive directories and incomplete/empty exports.
The test is included in CTest when `ENABLE_DTV_QA=ON` because it uses gr-dtv
transmit encoders.

Export writes several streams, retains decoded LLR tags until finalization,
and adds Python consumers/backpressure. Its memory/IO/scheduling cost is
intentional and unsuitable for baseline timing or unbounded live captures.
Feedback-based SNR estimation is asynchronous: changing scheduling can change
later demapping estimates. Compare decoders on the **same exported LLRs**,
not on separately demapped captures. Timing runs must omit `--export-dir`;
the normal receiver has reference tagging off by default.

### Recorded acceptance evidence

On 2026-10-21, the experiment was built on fork base
`ebed734575eeb90df43ce1dd062aece35822231f` in a disposable container based on
`wavescope-worker:pr1267-3ad42648` (GNU Radio 3.10.12.0, Python 3.14.4,
AVX2, AMD Ryzen 9 5950X). No running worker or worker image was changed.
All 22 CTest entries passed, including `qa_reference`. Focused Flake8, isort,
YAPF and changed-line clang-format 17 checks passed.

export-enabled FEC outputs against known transmitted bits.

The high-SNR 16APSK full-IQ capture with export disabled matched the original
binary's BCH output (SHA-256
`ca6f43e0e14c07bbf9824a41f35accb9fd06b3beb495fad145fcc8256a901b44`).
Do not generalize that to deterministic full-IQ decoding: repeated QPSK
captures differed even with the **original** binary, including when pinned
to one CPU. Its two original-binary output hashes were
`078478bc8eda76a96273e071de579bd38f9ad9237411f740acb94869a8b46eab`
and `6286f0bef4545dd7a28b6552b9d2b5aa71763ff8e111a0631ee7f042c5f3eeae`.
Identical-LLR replay is the discriminating comparison, not separately
synchronized/demapped runs. These failures remain visible; this experiment
does not diagnose or resolve the independently tracked
[getpwnam/wavescope#1274](https://github.com/getpwnam/wavescope/issues/1274)
high-SNR anomalies.

Three paired captures on logical CPU 0 measured median capture wall times
(graph setup, input hashing and export finalization included; interpreter
startup excluded):

| Case | Export disabled | Export enabled | Observed change |
| --- | ---: | ---: | ---: |
| MODCOD 6 normal, pilots off, 30 dB | 0.455 s | 0.465 s | +2.3% |
| MODCOD 19 normal, pilots off, 30 dB | 0.277 s | 0.450 s | +62.5% |

The shared host and short, acquisition-limited runs make these diagnostic
observations, not stable throughput claims. All paired enabled captures
replayed exactly. Keep taps out of baseline timing runs. A 2 dB short/pilot
QPSK recording emitted no frames and correctly failed export without a
completion manifest; it was not recorded as a successful empty comparison.
